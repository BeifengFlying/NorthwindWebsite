# 发布安全清单

## 每次发布前

- 运行 `npm run check`，确认没有密钥、邮箱、本机绝对路径或断链。
- 使用 `git status --ignored` 确认 `.env`、`private/`、`private-assets/`、`dist/`、`.DS_Store` 均被忽略。
- 只从 `public/assets/images` 引用公开 WebP，不直接引用原片。
- 检查照片画面内容，避免住址、证件、票据、车牌或未授权人物出现。
- 核对第三方音乐封面和其他素材的授权范围。
- 使用 `git ls-files` 复核公开仓库清单，确保没有原片、音频、视频或工程源文件。

## 密钥处理

将本机值写入 `.env`，并只在 `.env.example` 中记录变量名。前端静态代码无法保守秘密：任何会发送到浏览器的 API Key 都视为公开值，敏感调用必须放到服务端或托管平台函数中。

## 泄露响应

如果密钥已经提交，单纯删除文件并不能消除历史记录。应先在服务提供方撤销并轮换密钥，再清理 Git 历史；远程仓库为公开状态时还需按已泄露处理。

## 资源授权边界

公开仓库中的源码适用根目录 `LICENSE`。图片、摄影作品、音频、视频、封面、商标和其他创作资源不包含在源码许可中；优化后预览文件可被网站加载，不代表允许下载、转载、改编或商用。第三方素材的权利归各自权利人所有，公开前必须确认展示权或替换为自有素材。

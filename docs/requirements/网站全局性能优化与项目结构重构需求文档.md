# 网站全局性能优化、项目结构重构与 GitHub 版本管理需求文档

## 1. 项目背景

当前网站已经完成基础页面开发与视觉设计，但随着页面数量、资源文件以及功能不断增加，项目逐渐出现：

- 所有代码和资源集中在一个大文件夹
- 页面文件、图片、动画、配置文件混杂
- 后期维护困难
- 新增页面容易产生重复代码
- 项目版本无法有效追踪
- 修改错误后难以快速回退
- 缺少规范化备份机制

本次任务需要对整个网站项目进行：

1. 全局性能优化
2. 多终端适配优化
3. 项目目录结构重构
4. Git 版本管理建立
5. GitHub 远程备份配置
6. 隐私与敏感信息保护

目标：

打造一个：

- 高性能
- 易维护
- 可持续开发
- 安全可靠

的长期个人网站工程。

------

# 2. GitHub 桌面端与版本管理配置

## 2.1 打开并配置 GitHub Desktop

要求：

使用 GitHub Desktop 作为图形化 Git 管理工具。

执行：

- 打开 GitHub Desktop
- 登录个人 GitHub 账号
- 检测本地 Git 环境
- 将当前网站项目添加到 Git 管理

------

# 2.2 创建项目版本仓库

要求：

为当前网站项目建立 Git 仓库。

初始化：

```bash
git init
```

设置：

- 默认分支 main
- 配置用户信息
- 创建首次提交

首次提交：

```
Initial commit
网站项目初始版本备份
```

------

# 2.3 Git 提交规范

后续所有修改采用规范化提交。

格式：

```
类型: 修改内容
```

例如：

```
feat: 添加摄影作品页面

fix: 修复移动端布局问题

style: 优化首页视觉效果

perf: 优化图片加载速度

refactor: 重构项目目录结构
```

方便：

- 查看历史
- 定位问题
- 回滚版本

------

# 3. GitHub远程备份

## 3.1 创建远程仓库

要求：

将项目上传至 GitHub。

仓库设置：

- Private 或 Public 根据需求选择
- 保留完整提交历史
- 开启版本管理

------

# 3.2 自动备份流程

以后开发流程：

```
本地修改

↓

Git检测变化

↓

提交Commit

↓

Push到GitHub

↓

形成历史版本
```

保证：

任何时候都可以恢复之前版本。

------

# 4. 隐私保护要求（重要）

## 4.1 禁止上传敏感文件

创建：

```
.gitignore
```

忽略：

```
node_modules/

.env

.env.*

dist/

build/

.cache/

.DS_Store
```

------

# 4.2 个人隐私保护

禁止上传：

- 身份证信息
- 联系方式
- 私人文件
- 未公开账号信息
- 本地路径信息
- 密钥
- API Key
- Token

------

# 4.3 图片隐私保护

上传摄影作品前：

检查：

- EXIF信息
- GPS定位信息
- 拍摄设备信息

必要时：

清除图片元数据。

避免：

泄露：

- 拍摄地点
- 时间
- 设备信息

------

# 4.4 配置文件安全

禁止直接提交：

例如：

```
API_KEY=
SECRET=
PASSWORD=
TOKEN=
```

统一：

使用：

```
.env
```

并加入：

```
.gitignore
```

------

# 4.5 开源安全检查

如果选择公开仓库：

提交前检查：

- 是否包含私人照片
- 是否包含隐藏文件
- 是否包含未公开代码
- 是否包含第三方版权资源

# 6. 性能优化需求

## 图片优化

要求：

- WebP/AVIF转换
- 图片压缩
- 懒加载
- 响应式图片

------

## JavaScript优化

要求：

- 页面代码拆分
- 按需加载
- 删除无用依赖
- 减少重复逻辑

------

## 动画优化

保留：

- 页面转场
- 入场动画
- 滚动效果

优化：

优先：

- transform
- opacity

移动端：

自动降低：

- 粒子数量
- 动画复杂度
- 模糊效果
